A3T offers its platform as **MCP tools** (Model Context Protocol, JSON-RPC 2.0). The console uses them for flows, runs, resources and triggers; your code, Claude Code or any MCP client can use the same tools. Agents can be given them too.

For sign-in, agent calls and the other REST endpoints, see [HTTP API](../http/).

## Connect

| | |
|---|---|
| **Endpoint** | `POST $A3T_URL/message`, where `$A3T_URL` is the API address (see [HTTP API › The address](../http/#the-address)) |
| **Protocol** | JSON-RPC 2.0, one request per POST, answered in the response. MCP protocol version `2024-11-05` |
| **Methods** | `initialize`, `tools/list`, `tools/call` |
| **Auth** | `Authorization: Bearer $A3T_TOKEN`, a sign-in token from `POST /auth/login`. Agent keys (`a3tk_…`) can't call tools |
| **Discovery** | `GET /.well-known/oauth-protected-resource` says where an OAuth-aware client gets a token |

There is also the older SSE transport: `GET /sse` opens an event stream whose first `endpoint` event names where to post, and `POST /sse` takes requests. Prefer `POST /message`.

Every tool call runs **as you**: you see and change only the projects you may, and each call is checked against policy. A refused call comes back as a tool error that says why.

### List the tools

```bash
curl -s -X POST "$A3T_URL/message" \
  -H "Authorization: Bearer $A3T_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "tools/list"}'
```

The answer's `result.tools` lists each tool with its `name`, `description` and `inputSchema`.

### Call a tool

```bash
curl -s -X POST "$A3T_URL/message" \
  -H "Authorization: Bearer $A3T_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "id": 2, "method": "tools/call",
       "params": {"name": "list_flows", "arguments": {"namespace": "acme-support"}}}'
```

The answer:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "{ … }" }]
  }
}
```

| Part | What it is |
|---|---|
| `result.content[0].text` | The tool's answer. Most tools answer JSON as text: parse it. Some answer a sentence |
| `result.isError` | `true` when the tool failed or was refused; the text says why |

A JSON-RPC `error` (instead of `result`) means the request itself was wrong: an unknown method, or `params` that aren't `{name, arguments}`.

<Aside type="note">
**namespace** in the tools below is the project, as its namespace (for example `acme-support`). Where a tool shows a default, leaving it out uses that namespace. `a3t` and `system` are the platform's own.
</Aside>

## Flows

| Tool | What it does | Arguments |
|---|---|---|
| `list_flows` | Lists flows you may see | `namespace` (optional filter) |
| `get_flow` | One flow's full definition | `name`; `namespace` (default `default`); `version` (optional) |
| `create_flow` | Saves a flow. A released version never changes: saving the same version with other content is refused (`version_exists`) | `yaml` (CNCF Serverless Workflow 1.0.3) or `json` |
| `update_flow` | Turns a flow on or off, or sets its active version | `name`; `namespace`; `enabled`; `version` |
| `delete_flow` | Deletes a flow. Refused while it is deployed: undeploy it first | `name`; `namespace` |
| `propose_flow` | Checks a flow and shows it to the user to save, without saving it. For agents in the console | `yaml` |
| `propose_edit` | Proposes a whole changed document to the designer open in the console, without saving it. For agents in the console | `yaml` (the complete document); `summary` |
| `list_projects` | The projects that hold flows, resources or triggers, with counts. `platform` marks `a3t` and `system` | — |
| `check_conformance` | Which platform flows are on a base: covered, uncovered, exempt, broken | — |
| `list_task_types` | The task types a flow can use | `category`: `flow_control`, `io`, `ai`, `script` or `integration` (optional) |
| `get_task_type` | One task type in detail | `task_type`, such as `call:http`, `set`, `for` |

## Running flows

| Tool | What it does | Arguments |
|---|---|---|
| `execute_flow` | Runs a flow as you and **waits for its result** (up to 2 minutes by default). The text has the run's `Instance ID`, its status and its output. A run still going after that answers `running`; follow it with `get_execution_status` | `name`; `namespace` (default `default`); `input` (object) |
| `get_execution_status` | One run: `{instance_id, namespace, name, status, started_at, completed_at, current_step, duration_us, input, output, error}`. `status` is `Queued`, `Running`, `Suspended`, `Completed`, `Failed` or `Cancelled` | `instance_id` |
| `list_executions` | Recent runs, of one flow or of all | `namespace` and `name` (together, optional); `limit` (default 20) |

### Runs in detail and debugging

| Tool | What it does | Arguments |
|---|---|---|
| `list_runs` | Runs, newest first, with paging | `namespace` or `namespaces`; `name` (flow); `status` (list: `pending`, `running`, `waiting`, `suspended`, `completed`, `faulted`, `cancelled`); `limit` (default 50); `cursor` |
| `get_run` | One run: status, input, output, error, its steps with attempts and timing, and where it is paused | `run_id` |
| `get_run_journal` | What happened in a run, step by step, after a point | `run_id`; `after_seq` (default 0) |
| `start_run` | Starts a run, optionally as a debug run | `namespace`; `name`; `input`; `debug`; `breakpoints` (`[{step_key, when: before \| after \| on_error, condition?, hit?}]`); `pause_on_start` |
| `debug_run` | Moves a paused debug run on | `run_id`; `command`: `continue`, `step_over`, `step_into`, `step_out`, `run_to` (with `step_key`) or `stop` |
| `set_breakpoints` | Replaces a debug run's breakpoints | `run_id`; `breakpoints` |
| `edit_step_input` | Changes a step's input while a debug run is paused before it | `run_id`; `step_key`; `input` |
| `cancel_run` | Cancels a run | `run_id`; `reason` |
| `rerun_run` | Starts a new run like this one, from the start or from a journal point | `run_id`; `from_seq`; `input`; `debug`; `breakpoints` |
| `send_event` | Sends a CloudEvent into a project: runs waiting for it wake up | `namespace`; `event` (`{type, source?, subject?, data?, …}`) |

Reading a run needs read access to its project; starting one needs run access; debugging, cancelling and re-running need write access.

## Agents

| Tool | What it does | Arguments |
|---|---|---|
| `list_agents` | The agents you may see, as their records | `org_id` (default: the default organisation) |
| `get_agent` | One agent's record and session state | `agent_id` |
| `send_message` | Sends a message to an agent and waits for the answer. For apps, `POST /chat` is the way to call an agent: it streams, and takes agent keys | `agent_id`; `message`; `context` |
| `get_agent_history` | A session's conversation history | `agent_id` (the session key); `limit` (default 50) |
| `clear_agent_session` | Clears a session's history | `agent_id` |
| `create_agent`, `delete_agent` | Make and delete agents of FlowR's built-in agent runner. **A3T agents**, the ones in the console, are made and deleted through `agent_a3t_agents`; see [HTTP API › Agents: control plane](../http/#agents-control-plane) | `template`, `namespace`, `agent_id`, `config`, `triggers` / `agent_id` |
| `list_agent_templates` | Agent templates and their versions | `namespace` (optional) |
| `get_agent_template` | One template, active version or `name:version` | `name`; `namespace` (default `default`) |
| `create_agent_template` | Registers a template version | `name`; `version`; `spec`; `namespace`; `description`; `tags`; `defaults` |
| `list_permissions` | What the user allowed or declined in the current conversation. Only works inside an agent's conversation, not over `/message` | `only`: `denied`, `granted` or `all` |

## Resources

| Tool | What it does | Arguments |
|---|---|---|
| `list_resources` | Resources you may see. Keys and passwords come back masked | `namespace`; `type_ref` (such as `openai`, `postgres`) |
| `get_resource` | One resource | `name`; `namespace` (default `default`) |
| `create_resource` | Makes a resource | `name`; `type_ref`; `config`; `namespace`; `description` |
| `delete_resource` | Deletes a resource. A canvas still in use is refused | `name`; `namespace` |
| `list_resource_types` | The resource types you can make | `category`: `database`, `key_value`, `vector`, `queue`, `api`, `storage`, `ai`, `agent`, `mcp`, `memory`, `channel` or `custom` (optional) |
| `query_resource` | Runs a query with the resource's driver and returns rows. ADB resources take AQL, e.g. `RECALL FROM WORKING WHERE name = "alice"` | `resource`; `query`; `namespace` (default `default`); `variables` |
| `list_mcp_tools` | The tools an MCP server resource offers. Without `name`, lists the MCP servers in the namespace | `name`; `namespace` (default `a3t`) |

To change a resource's config, use `PUT /registry/resources/{project}/{name}` ([HTTP API › Resources](../http/#resources)).

## Triggers

A trigger fires on a webhook, a schedule, an ADB topic or a platform event, and sends to its targets. See [Triggers](../../console/triggers/).

| Tool | What it does | Arguments |
|---|---|---|
| `list_triggers` | Triggers you may see | `namespace`; `target_flow` (triggers that run this flow) |
| `get_trigger` | One trigger | `id` |
| `create_trigger` | Makes a trigger | `name`; `namespace` (default `default`); `description`; `config`; `targets`; `enabled` (default true) |
| `update_trigger` | Changes a trigger; give only what changes | `id`; `name`; `namespace`; `description`; `config`; `targets`; `enabled` |
| `delete_trigger` | Deletes a trigger. Its webhook answers 404 at once | `id` |
| `enable_trigger` / `pause_trigger` | Resumes or pauses it | `id` |
| `attach_trigger` | Adds a target | `id`; `target` |
| `detach_trigger` | Removes a target | `id`; `target_id` (the flow name, agent id or URL) |

`config` is one of:

| `type` | Fields |
|---|---|
| `webhook` | `path`, such as `/acme/refund`. Called at `POST /webhook/acme/refund` |
| `cron` | `expression`, such as `*/5 * * * *` |
| `event` | `source` |
| `adb_topic` | `resource` (`project/adb-resource`), `topic`, `filter` (optional, `{field: value}`) |

A target is `{type: "workflow", namespace, name}`, `{type: "agent", agent_id}` or, for `attach_trigger`, `{type: "webhook", url}`.

```json
{
  "jsonrpc": "2.0", "id": 3, "method": "tools/call",
  "params": {
    "name": "create_trigger",
    "arguments": {
      "name": "refund-requests",
      "namespace": "acme-support",
      "config": { "type": "webhook", "path": "/acme/refund" },
      "targets": [{ "type": "workflow", "namespace": "acme-support", "name": "flow_acme_support_refund" }]
    }
  }
}
```

## Deploying: canvases and runtimes

A **canvas** says where and how a flow runs; a **preset** is a canvas to start from. Nothing is placed until `deploy_flow`. See [Canvas](../../console/canvas/).

| Tool | What it does | Arguments |
|---|---|---|
| `list_canvas_presets` | The presets to choose from | — |
| `get_canvas` | One canvas or preset in full | `name`; `namespace` (default `a3t`) |
| `clone_canvas` | Copies a preset into a new canvas, with changes. The preset is never changed | `preset`; `name`; `preset_namespace` and `namespace` (default `a3t`); `patch` (shaped like the canvas; arrays replace) |
| `bind_canvas` | Attaches a canvas to a flow, which makes it deployable | `name`; `flow` (`namespace/name`); `namespace` |
| `update_canvas` | Changes a flow's canvas. Presets can't be changed: clone them | `name`; `patch`; `namespace` |
| `list_runtimes` | The runtimes a flow can be placed on, with their labels | — |
| `preview_placement` | Where a flow would be deployed, without deploying | `name`; `namespace` (default `a3t`); `runtime` (optional) |
| `deploy_flow` | Deploys a flow. Production, or a dedicated runtime, needs approval: over `/message` that is decided by policy at once, with nobody to ask | `name`; `namespace` (default `a3t`); `runtime` (optional) |
| `create_runtime` | Registers a runtime pool. Admin | `name`; `labels` (such as `{"tier": "test"}`); `namespace`; `url` |

## Operating deployments

| Tool | What it does | Arguments |
|---|---|---|
| `list_deployments` | Every runtime, what is deployed on it, its state, recent activity and the host's CPU, memory and disk | — |
| `probe_deployment` | A live look at one deployment: serving or not, last runs, triggers, health checks | `deployment` (its id, a flow `namespace/name`, or an agent id) |
| `pause_deployment` | Refuses every new request until resumed; runs in progress finish | `deployment`; `reason` |
| `resume_deployment` | Serves again | `deployment` |
| `restart_deployment` | Re-reads its placement from its canvas | `deployment` |
| `undeploy` | Removes the deployment; the flow and canvas stay | `deployment` |
| `terminate_deployment` | Cancels its runs now, then removes it | `deployment` |
| `terminate_runtime` | Admin. Removes a runtime and reschedules what ran there. Call without `confirm` to see the plan; call again with `confirm` set to its name | `runtime`; `confirm` |
| `set_runtime_state` | Admin. `active`, `hibernated` (sleeps until the next request) or `paused` | `runtime`; `state` |
| `set_paused_response` | Admin. What webhooks get while paused: `503` or `404` | `runtime`; `status` |

| `set_state` | Writes a value, optionally with an expiry | `key`; `value`; `ttl_secs` |
